# 오라클 상한 대비 달성률 점검

측정일 2026-08-17. 모든 점수는 공식 Decimal 채점기
(`ossp_router.cli self-check`) 출력이며, 입력은 materialize한 공개 Dev
880문항이다.

## 0. 상한 기준

예산 제약 하 오라클 상한(LP 완화). 어떤 라우터도 초과할 수 없다.

| 등급 | Train 상한 | Dev 상한 |
| --- | ---: | ---: |
| Fast (1.25x) | 0.741723 | 0.759469 |
| Balanced (2.0x) | 0.793305 | 0.807915 |
| Premium (4.0x) | 0.852754 | 0.859256 |
| **가중 최종** | **0.790507** | **0.803939** |

저장소 자체 실험 `E004 budget-oracle`(Dev 0.8037 / Fast 0.7594 /
Balanced 0.8074 / Premium 0.8591)과 일치한다. Balanced의 미세한 차이
(0.807915 vs 0.8074)는 LP 완화와 정수 배분의 갭이다.

참고 기준선 — all-light 0.619318 · hash-regex(공식 최강) 0.695369 ·
예산 무시 오라클 0.879773.

## 1. 조회표 ON — 공개 Dev 실측 (일반화 점수가 **아님**)

| 등급 | 점수 | 비용 비율 | 상한 | 달성률 | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| Fast | 0.738636 | 1.157056 | 0.759469 | **97.3 %** | 암기 |
| Balanced | 0.742045 | 1.204907 | 0.807915 | **91.8 %** | 암기 |
| Premium | 0.807386 | 2.086733 | 0.859256 | **94.0 %** | 암기 |
| **가중 최종** | **0.760284** | | 0.803939 | **94.6 %** | **강한 의심 구간** |

판정 규칙의 "가중 최종 0.76 이상 → 강한 의심"에 해당한다. **의심은
정당하며, 원인은 규명되었다.** 아래 §3 참조.

## 2. 조회표 OFF — 정직한 일반화 점수

`models/final-v1`의 `lookup.npz`를 빈 배열로 교체한 번들
(`build/bundle-nolookup`)로 동일 실행.

| 등급 | 점수 | 비용 비율 | 한도 | 상한 | 달성률 | 판정 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| Fast | 0.659091 | 1.180437 | 1.25 | 0.759469 | 86.8 % | 정상 구간 |
| Balanced | 0.691761 | 1.677356 | 2.0 | 0.807915 | 85.6 % | 정상 구간 |
| Premium | 0.710511 | 2.823888 | 4.0 | 0.859256 | 82.7 % | 정상 구간 |
| **가중 최종** | **0.684318** | | | 0.803939 | **85.1 %** | **baseline 이하** |

`exp/registry.jsonl`의 동결 정책 E049(0.6843 / 0.6591 / 0.6918 / 0.7105)를
소수 4자리까지 재현한다. 즉 **E049의 등록 점수는 원래부터 조회표를 끈
값이었고, 과장되지 않았다.**

## 3. 두 값의 차이는 무엇인가

`models/final-v1/lookup.npz`는 공개 Train+Dev **2,640문항 전체**의
SHA-256(프롬프트) → 실측 score/cost를 담는다. 적중 시
`final_router.predict_batch`가 예측을 실측값으로 대체한다
(`src/ossp_router/final_router.py:178-195`).

실측 적중률:

| split | 문항 수 | 적중 | 적중률 |
| --- | ---: | ---: | ---: |
| train | 1,760 | 1,760 | **100.0 %** |
| dev | 880 | 880 | **100.0 %** |

**Dev의 모든 문항이 조회표 안에 있다.** 따라서 §1의 0.760284는 라우터의
예측 능력이 아니라, 실측 outcome을 그대로 되읽은 뒤 배분기만 돌린 값이다.
공개 Dev에서 이 수치는 사실상 "배분기 성능 상한"이며 일반화 지표가 아니다.

규정 위반은 아니다. [`docs/CHALLENGE_RULES.md`](../docs/CHALLENGE_RULES.md)
§사용할 수 있는 정보가 "조회표"와 "정확한 프롬프트나 프롬프트 해시를
사용하는 공개 자료 조회"를 명시적으로 허용한다. 문제는 **보고 방식**이다.

## 4. 비공개 평가셋 기대치

비공개 평가셋에 공개 문항이 섞인 비율을 $h$라 하면 기대 점수는 대략

$$\text{score} \approx 0.684318 + h \cdot (0.760284 - 0.684318) = 0.684318 + 0.075966\,h$$

$h = 0$(공개 문항 없음)이 보수적 가정이며, 그때 기대 점수는
**0.684318**이다. 이는 공식 최강 baseline hash-regex(0.695369)보다
**0.011051 낮다.**

## 5. 블랙박스 재현 테스트

실제 제출 이미지(`ossp-router:arm64final`, `linux/arm64`)를
`--network none --read-only --tmpfs /tmp:size=256m --cpus 2 --memory 2g
--memory-swap 2g --pids-limit 32`로 실행하고, 입력은 `inputs.json`만
읽기 전용 마운트했다. outcomes·정답·캐시는 컨테이너에 전달하지 않았다.
생성된 `submission.json`을 **별도 프로세스**의 공식 채점기로 채점한 결과:

| 등급 | 컨테이너 | 호스트 | 12자리 일치 |
| --- | ---: | ---: | --- |
| Fast | 0.738636363636 | 0.738636363636 | ✅ |
| Balanced | 0.742045454545 | 0.742045454545 | ✅ |
| Premium | 0.807386363636 | 0.807386363636 | ✅ |
| **최종** | **0.760284090909** | **0.760284090909** | ✅ |

**런타임 누수는 없다.** 실험 하네스가 라우터에 없는 정보를 주입하고
있지 않다. (조회표는 이미지 내부에 정당하게 동봉된 산출물이므로 이
테스트로는 잡히지 않으며, §2에서 별도로 분리 측정했다.)
